================================================================================

In Terminal 2, capture all [SubmitDebug] lines. Look for:

  [SubmitDebug] endpoint=/form/submit
  [SubmitDebug] url=http://10.10.18.254:3002/form/submit?form_slug=...
  [SubmitDebug] answersCount=X
  [SubmitDebug] filesCount=Y
  [SubmitDebug] payload=[{"jawaban":...}...]
  [SubmitDebug] answer[0] soal_id=... has_option=... has_text=...
  [SubmitDebug] SUBMIT_SENDING
  [SubmitDebug] SUBMIT_RESPONSE_RECEIVED
  [SubmitDebug] statusCode=???  ← ⭐ CHECK THIS NUMBER
  [SubmitDebug] responseBody={...}  ← ⭐ CHECK THIS BODY
  [SubmitDebug] SUBMIT_SUCCESS or SUBMIT_ERROR

CRITICAL NUMBERS TO RECORD:
  ✓ statusCode = ???  (e.g., 200, 201, 500, 422, etc.)
  ✓ responseBody = {what backend returned}

================================================================================
STEP 6: INTERPRET RESULTS (2 minutes)
================================================================================

IF statusCode = 200 or 201:
  ✅ SUCCESS! Form submitted successfully
  → Feature is working correctly
  → No further action needed

IF statusCode = 500:
  ⚠️ SERVER ERROR (not mobile issue)
  → Backend returning internal server error
  → Backend team needs to check server logs
  → Report: statusCode=500 + responseBody to backend team

IF statusCode = 4xx (e.g., 400, 422):
  ⚠️ VALIDATION ERROR
  → Backend validation failed
  → Check payload structure in logs
  → Verify all soal_id present (not null)
  → Verify options/text present for each answer

IF no [SubmitDebug] logs appear:
  ❌ CONNECTION ERROR
  → Device cannot reach backend
  → Check: Network connectivity
  → Check: Backend server running at 10.10.18.254:3002
  → Check: IP address correct
